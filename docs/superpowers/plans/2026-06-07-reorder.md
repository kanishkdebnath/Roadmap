# Phase 6 — Drag-to-Reorder Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** Let the user drag-reorder milestones within a roadmap and steps within a milestone on the detail screen; the new order persists across app restarts via contiguous `position` values (spec F3.4, F4.5, §7.4).

**Architecture:** The persistence backend already exists and is JVM-tested — `RoomRoadmapRepository.reorderMilestones(roadmapId, orderedIds)` and `reorderSteps(milestoneId, orderedIds)` rewrite the contiguous `position` sequence inside `db.withTransaction`, guarded by `domain.isValidReorder` (permutation check). Phase 6 only adds: (1) the `sh.calvin.reorderable` dependency, (2) thin `RoadmapDetailViewModel` wrappers, and (3) drag UI on the detail screen. The screen keeps a **local mutable snapshot** of the milestone/step lists that the reorderable library mutates live during a drag; on drop we persist the new id order, and the next Room `Flow` emission re-seeds the snapshot (same order → no flicker).

**Tech Stack:** Kotlin · Jetpack Compose · `sh.calvin.reorderable:reorderable:3.1.0` (Maven Central) — `rememberReorderableLazyListState` + `ReorderableItem` for the milestone `LazyColumn`, `ReorderableColumn` for the per-card step list, `Modifier.draggableHandle()` on the existing `DragGrip` icon. ViewModel logic is TDD'd via Robolectric; the drag gestures themselves are verified on the emulator (no Compose UI unit tests in this module).

**Reorderable API note:** The code below follows the library's canonical README pattern (stable across 2.x/3.x). If the resolved 3.1.0 artifact exposes slightly different symbol names, fix them at the compile step — do not change the persistence contract (`onDrop → reorder*(orderedIds)`).

```kotlin
    ) { inner ->
        // Local snapshot the drag mutates live; re-seeded whenever Room re-emits.
        var milestones by remember(tree.milestones) { mutableStateOf(tree.milestones) }
        val listState = rememberLazyListState()
        // Reorder by KEY, not raw index: this LazyColumn also holds non-milestone
        // items (header, "Milestones · N" label, AddInline), so onMove's from/to
        // indices are absolute LazyColumn positions, not indices into `milestones`.
        val reorderState = rememberReorderableLazyListState(listState) { from, to ->
            milestones = milestones.toMutableList().apply {
                val fromIndex = indexOfFirst { it.milestone.id == from.key }
                val toIndex = indexOfFirst { it.milestone.id == to.key }
                if (fromIndex != -1 && toIndex != -1) add(toIndex, removeAt(fromIndex))
            }
        }
        LazyColumn(
            Modifier.padding(inner).fillMaxSize(),
            state = listState,
            contentPadding = PaddingValues(bottom = 96.dp),
        ) {
```

Note: `from.key` / `to.key` are the `key` values supplied to `items(...)` / `ReorderableItem(...)` — here the milestone ids (`Long`). The `!= -1` guard skips any move that lands on a non-milestone item.
