# Roadmap (Android) — Product Specification

**Status:** Draft v1
**Date:** 2026-06-05
**Provenance:** Feature-extracted from the *pathforge* web roadmaps module (fully implemented), adapted to a **local-only, single-user Android app**.

---

## 1. Overview & Goals

Roadmap is an offline-first goal-tracking app for Android. A single user turns a goal into an ordered checklist: a **roadmap** holds ordered **milestones**, each milestone holds ordered **steps**, and each step can carry reference **links**. Milestones complete automatically when all their steps are checked off, and a ring shows overall progress.

**Goals**

- **Structure a goal into doable pieces.** Roadmap → milestones → steps, all reorderable.
- **Derived progress.** Check steps; milestones and the roadmap ring update themselves. A milestone is "done" when every step in it is done.
- **Deadlines & overdue awareness.** Optional deadlines on a roadmap and its milestones; overdue items are visually flagged.
- **Own your data.** Everything lives on-device. Paste-JSON import/export is the portability mechanism.
- **Fast capture.** Inline add for milestones and steps; bulk-import a whole roadmap from JSON (e.g. one generated by an LLM elsewhere).

**Target user.** An individual planning a personal goal, project, or learning path on their phone who wants an ordered, checkable structure with progress tracking — without an account, subscription, or network connection.

---

## 2. Non-Goals (v1)

- **No accounts, login, or auth.** Single user per device install.
- **No cloud sync or multi-device.** Data is local. (See §13 Deferred.)
- **No in-app AI generation / network calls.** Import accepts pasted JSON only; the app never calls an LLM or any API. (See §8.)
- **No step interdependencies / blocking.** Steps are independent; a milestone is simply "all steps complete."
- **No collaboration / sharing of live roadmaps.** Export is a static JSON snapshot.
- **No cross-feature links** (to budget, resources, job applications). Roadmap is self-contained.

---

## 3. User Stories

**List (the Roadmaps screen)**
- As a user, I can see all my roadmaps as cards, each with a progress ring and (if set) a deadline.
- As a user, I can switch between **Active** and **Archive** with a segmented control.
- As a user, I can search roadmaps by title, description, or milestone titles.
- As a user, I can create a new roadmap, or import one from pasted JSON.

**Detail (a single roadmap)**
- As a user, I can see the roadmap's title, description, deadline, and overall progress ring.
- As a user, I can add, edit, reorder, and delete milestones.
- As a user, within a milestone I can add, edit, reorder, check off, and delete steps.
- As a user, I can attach reference links to a step and tap them to open in my browser.
- As a user, when I check the last incomplete step in a milestone, the milestone marks itself done.
- As a user, I can edit the roadmap, archive/unarchive it, or delete it.

**Import**
- As a user, I can copy a prompt template, paste it into any LLM, get JSON back, paste it into the app, and import a full roadmap (milestones + steps + links) in one action.

## 5. Functional Requirements

Notation: timestamps are epoch millis (`Long`); deadlines are date-only ISO-8601 strings (`YYYY-MM-DD`); ordering is an explicit `position` integer (0-based).

### F1 — Roadmaps list

- **F1.1** Show all roadmaps for the selected scope as cards. Default scope = **Active** (`archived = false`).
- **F1.2** A **segmented control** toggles **Active** ↔ **Archive** (`archived = true`).
- **F1.3** Each card shows: title, optional description preview, a **progress ring** (% steps complete), milestone count, and deadline (with overdue styling if applicable).
- **F1.4** **Search** filters the current scope by matching the query against roadmap title, description, **and** any milestone title (case-insensitive substring).
- **F1.5** Sort roadmaps by `updatedAt` DESC.
- **F1.6** Empty states: distinct messaging for "no roadmaps yet" (with Create/Import calls to action) vs. "no results for this search."
- **F1.7** Actions: **New roadmap** (dialog) and **Import** (paste-JSON, see F8).

**Acceptance:** Creating a roadmap shows it at the top of Active; archiving it moves it to Archive; searching a milestone's title surfaces its parent roadmap.

### F2 — Roadmap CRUD

- **F2.1** Create with: `title` (required, 1–200), `description` (optional, ≤2000), `deadline` (optional date).
- **F2.2** Edit any of title/description/deadline; clearing deadline/description removes it.
- **F2.3** **Archive / unarchive** toggles `archived`.
- **F2.4** **Delete** removes the roadmap and **cascades** to its milestones, steps, and links (confirm first).

**Acceptance:** Deleting a roadmap with milestones and steps removes all descendant rows; no orphans remain.

### F3 — Milestones

- **F3.1** A roadmap has 0–N ordered milestones. Add with `title` (1–200), optional `description` (≤2000), optional `deadline`.
- **F3.2** Inline "add milestone" affordance at the end of the list, plus a dialog for full fields.
- **F3.3** Edit title/description/deadline; delete (cascades to its steps & links; confirm).
- **F3.4** **Reorder** milestones by drag; the new order persists via updated `position` values.
- **F3.5** A milestone displays its own progress (steps done / total) and an overdue flag if past deadline and not complete.

**Acceptance:** Dragging milestone 3 above milestone 1 persists across app restarts.

### F4 — Steps

- **F4.1** A milestone has 0–N ordered steps. Add with `title` (1–200) and 0–N links.
- **F4.2** Inline "add step" affordance within each milestone.
- **F4.3** **Toggle complete:** tapping a step's checkbox flips `completed`; on completion `completedAt = now`, on un-completion `completedAt = null`. This triggers milestone completion recompute (F6).
- **F4.4** Edit step title and links; delete a step (recomputes milestone completion).
- **F4.5** **Reorder** steps within a milestone by drag; order persists via `position`.

**Acceptance:** Checking every step in a milestone marks the milestone done and fills its ring; unchecking one reverts both.

### F5 — Links

- **F5.1** A step has 0–N links, each `url` (required) + `label` (optional).
- **F5.2** **URL validation:** only `http://` or `https://` URLs are accepted (reject others on entry and on import — see §8).
- **F5.3** Links render as chips/rows; the display text is `label` when present, else the URL.
- **F5.4** Tapping a link opens it in the device browser (Android `ACTION_VIEW` intent).

### F6 — Derived completion

- **F6.1** A milestone is **complete** iff it has ≥1 step and **all** steps are `completed`. On any step add/edit/toggle/delete, recompute: set `milestone.completedAt = now` when newly complete, clear it (`null`) otherwise.
- **F6.2** A milestone with 0 steps is never complete (`completedAt = null`).
- **F6.3** Step `completedAt` is independent and set/cleared on its own toggle.

### F7 — Progress & overdue

- **F7.1** **Roadmap progress** = `completedSteps / totalSteps` across all its milestones (0 when no steps), rendered as a ring (conic-style) showing the percentage; a checkmark replaces the number at 100%.
- **F7.2** **Milestone progress** = its own done/total steps.
- **F7.3** **Overdue:** a roadmap or milestone with a `deadline` strictly before *today* (local date) **and** not complete is flagged overdue (red accent). Complete items are never overdue.

### F8 — Paste-JSON import

- **F8.1** The Import flow has two panels: a **Prompt** panel (a read-only, copyable prompt template the user can paste into any LLM) and a **Paste** panel (a textarea for the resulting JSON).
- **F8.2** On import, validate the pasted JSON against the bulk schema (§8). On success, create the entire roadmap tree (roadmap + milestones + steps + links) in **one atomic transaction**, assigning `position` by array index. On failure, show a clear validation error and import nothing.
- **F8.3** Imported roadmaps appear in **Active**.

**Acceptance:** Pasting valid JSON for a 3-milestone roadmap creates it fully; pasting malformed JSON or a non-http link surfaces an error and creates nothing.

### F9 — JSON export

- **F9.1** Export a single roadmap (or all roadmaps) to a JSON document matching the import schema, delivered via the Android share sheet / "Save to Files."
- **F9.2** Exported JSON re-imports cleanly (round-trip safe).

## 6. Data Model

Pathforge stores roadmaps as a single embedded MongoDB document. SQLite/Room has no native arrays, so the tree is modeled **relationally** with explicit `position` ordering and `ON DELETE CASCADE` foreign keys. **No `userId`** (single user). Four entities.

> **Cascade:** `roadmap → milestone → step → link` all use `ForeignKey(onDelete = CASCADE)` so deleting a parent cleans up descendants.

### 6.1 Roadmap  (table `roadmap`)
| Field | Type | Notes |
|-------|------|-------|
| `id` | `Long` PK autoGenerate | |
| `title` | `String` | 1–200 chars |
| `description` | `String?` | ≤2000 chars |
| `deadline` | `String?` | ISO-8601 date `YYYY-MM-DD` |
| `archived` | `Boolean` | default `false` |
| `createdAt` / `updatedAt` | `Long` | epoch millis |

Index: `(archived, updatedAt)`.

### 6.2 Milestone  (table `milestone`)
| Field | Type | Notes |
|-------|------|-------|
| `id` | `Long` PK autoGenerate | |
| `roadmapId` | `Long` FK → roadmap (CASCADE) | |
| `title` | `String` | 1–200 chars |
| `description` | `String?` | ≤2000 chars |
| `deadline` | `String?` | ISO-8601 date |
| `position` | `Int` | 0-based order within roadmap |
| `completedAt` | `Long?` | derived (F6); set when all steps done |
| `createdAt` / `updatedAt` | `Long` | |

Index: `(roadmapId, position)`.

### 6.3 Step  (table `step`)
| Field | Type | Notes |
|-------|------|-------|
| `id` | `Long` PK autoGenerate | |
| `milestoneId` | `Long` FK → milestone (CASCADE) | |
| `title` | `String` | 1–200 chars |
| `completed` | `Boolean` | default `false` |
| `completedAt` | `Long?` | set on completion, cleared otherwise |
| `position` | `Int` | 0-based order within milestone |
| `createdAt` / `updatedAt` | `Long` | |

Index: `(milestoneId, position)`.

### 6.4 Link  (table `link`)
| Field | Type | Notes |
|-------|------|-------|
| `id` | `Long` PK autoGenerate | |
| `stepId` | `Long` FK → step (CASCADE) | |
| `url` | `String` | must start `http://` or `https://` |
| `label` | `String?` | optional display text |
| `position` | `Int` | 0-based order within step |

Index: `(stepId, position)`.

> **Read model:** the detail screen loads a `RoadmapWithChildren` via a Room `@Relation` (roadmap → milestones → steps → links), each level ordered by `position ASC`, exposed as a `Flow` for reactive UI.

## 7. Business Logic

### 7.1 Completion derivation
`recomputeMilestoneCompletedAt(steps)` → `now` if `steps.isNotEmpty() && steps.all { it.completed }`, else `null`. Called within the same transaction as any step add / toggle / edit / delete that could change a milestone's completeness.

### 7.2 Progress
- Roadmap %: `completedSteps / totalSteps` over all milestones (guard divide-by-zero → 0%).
- Milestone %: its own completed/total.
- Both feed the `RingProgress` component (§9); 100% shows a checkmark.

### 7.3 Overdue
`isOverdue(deadline, isComplete)` = `deadline != null && LocalDate.parse(deadline) < LocalDate.now(zone) && !isComplete`. Computed in the **device local timezone**.

### 7.4 Reordering
Reorder operations rewrite the contiguous `position` sequence (0..n-1) for the affected sibling set in one transaction. Validate that the submitted id set is a permutation of existing sibling ids (no adds/drops) before applying — mirrors pathforge's `validateReorderIds`.

### 7.5 Import validation & insertion
Validate against the bulk schema (§8); reject the whole payload on any violation. On success, insert roadmap → milestones → steps → links in a single transaction, assigning `position` from array index, recomputing each milestone's `completedAt` from its (imported) step states.

## 8. Import / Export JSON Schema

Mirrors pathforge's `BulkRoadmapRequest`, with bounds that double as anti-abuse limits.

```jsonc
{
  "title": "string (1–200, required)",
  "description": "string (≤2000, optional)",
  "deadline": "YYYY-MM-DD (optional)",
  "milestones": [
    {
      "title": "string (1–200, required)",
      "description": "string (≤2000, optional)",
      "deadline": "YYYY-MM-DD (optional)",
      "steps": [
        {
          "title": "string (1–200, required)",
          "completed": false,
          "links": [
            { "url": "https://… (http/https only)", "label": "string (optional)" }
          ]
        }
      ]
    }
  ]
}
```

**Validation rules**
- Title required and 1–200 chars at every level that has one; descriptions ≤2000.
- `links[].url` MUST start with `http://` or `https://` — reject anything else (defense against malformed/LLM-injected URLs).
- Reasonable array caps (e.g. milestones ≤ 100, steps ≤ 200/milestone, links ≤ 20/step) to bound a single import.
- Unknown fields ignored; malformed JSON → single clear error, nothing imported.

**Prompt template (Import → Prompt panel, copyable).** A static instruction block telling an LLM to emit exactly this JSON shape for a goal the user describes — so the user can generate a roadmap in any chat tool and paste the result back. The app itself makes no network calls.

## 9. UI / Screens & Visual Design

The implemented pathforge aesthetic (the "redesign", which superseded the original Editorial Manuscript look) is the reference.

**Design language**
- **Typography:** Inter throughout; **tabular numerals** for counts/percentages.
- **Palette / tokens:** `brand` = sky-500 (primary), `done` = emerald-500, `overdue` = red-600. Slate neutrals. Full **dark mode**.
- **RingProgress:** conic-style progress ring (Compose `Canvas` `drawArc`), two sizes — ~28dp (cards/milestones) and ~96dp (detail sidebar); renders a checkmark at 100%.
- **Cards:** gradient icon tile, title, description preview, ring, deadline; subtle **stagger animation** on list load.
- **Segmented control:** Active / Archive toggle on the list.
- **Step check:** brief check/strike animation on toggle.

**Screens**
| Screen | Features | Key UI |
|--------|----------|--------|
| **Roadmaps list** | F1, F2 (create), F8 (import) | Toolbar (segmented control + search), card grid, empty/no-results states, New + Import dialogs |
| **Roadmap detail** | F2–F7 | **Responsive:** stacked on phone (header block = title/description/ring/actions, then milestone list), **two-column** on tablet/landscape (sidebar + main). Milestone cards with drag handles; step rows with checkbox, inline edit, link chips; inline add for milestones/steps |
| **Dialogs** | F2/F3/F4/F8 | New/Edit Roadmap, New/Edit Milestone, Edit Step Links, Delete confirms, Import (Prompt + Paste panels) |

**Interactions**
- Drag-to-reorder milestones and steps.
- Because writes are local, edits reflect immediately via Room `Flow` (no optimistic-update bookkeeping needed — the web app's optimistic layer collapses to direct local writes).

## 10. Non-Functional Requirements

- **Offline:** 100% functional with no network; no runtime network permission required. Opening a link hands off to the browser via intent.
- **Reactivity:** screens observe Room `Flow`; list, rings, and completion states update without manual refresh.
- **Atomicity:** delete-cascade, reorder, step-toggle+recompute, and import are single Room `@Transaction`s.
- **Integrity:** `position` sequences stay contiguous; cascades prevent orphans; import is all-or-nothing.
- **Performance:** instant list/detail for typical data (tens of roadmaps, hundreds of steps); import parses/inserts off the main thread.
- **Privacy / data ownership:** data never leaves the device except via explicit user export/share; no analytics transmitting roadmap content in v1.
- **Accessibility:** overdue/done states carry text/icon, not color alone; checkboxes and drag handles are touch-friendly; Material 3 dynamic color / dark theme.
- **Resilience:** Room schema versioned with migrations; import/parse errors surface clearly, never a silent partial write.

## 11. Recommended Android Stack

| Concern | Choice | Notes |
|---------|--------|-------|
| Language | **Kotlin** | Coroutines + Flow throughout. |
| UI | **Jetpack Compose + Material 3** | Two screens: List, Detail. |
| Navigation | **Navigation-Compose** | List → Detail (roadmap id arg). |
| Persistence | **Room** (SQLite) | Relational entities (§6); `@Relation` read model; `@Transaction` for atomic ops; FK `onDelete = CASCADE`. |
| State | **ViewModel + StateFlow** | Per-screen view models over a repository. |
| Reorder | **Compose reorderable list** (e.g. a sortable/reorderable Compose lib) | Drag milestones & steps; persist `position`. |
| Progress ring | **Compose `Canvas` / `drawArc`** | Conic-style ring, two sizes, checkmark at 100%. |
| Date | **java.time `LocalDate`** | Deadlines + overdue (local TZ). |
| JSON import/export | **kotlinx.serialization** | Parse/validate the bulk schema (§8); serialize for export. |
| Links | `Intent.ACTION_VIEW` + `FileProvider` (export share) | Open URLs; share JSON. |
| Prefs (optional) | **DataStore** | Theme / minor settings. |
| Min SDK | **API 26** | `java.time` without desugaring (or API 24 + desugaring). |
| DI (optional) | Hilt | Optional; repository wiring is simple. |

**Suggested package layout:** `data` (Room entities, DAOs, repository, JSON (de)serializers) · `domain` (completion/progress/overdue/reorder logic, import validation) · `ui` (Compose list + detail + dialogs, view models) · `ui.components` (RingProgress, SegmentedControl, MilestoneCard, StepRow, LinkChips).

## 12. Adaptations Log (pathforge web → Android local)

| # | pathforge web | Roadmap (Android) | Rationale |
|---|---------------|-------------------|-----------|
| 1 | Every entity carries `userId`; queries filter by it | **Dropped** | Single user, single device. |
| 2 | Embedded Mongo document (milestones[]→steps[]→links[]) | **Relational Room tables** with FKs + CASCADE | SQLite has no embedded arrays; relational is idiomatic and queryable. |
| 3 | Array index = canonical order | **Explicit `position` Int**; reorder rewrites positions | SQL rows are unordered; need an order column. |
| 4 | 13 REST endpoints + bulk import | **Repository / use-case operations** (same 14 ops) | No server; same operations as local methods. |
| 5 | LLM-from-prompt bulk import (`POST /bulk`) | **Offline paste-JSON import + copyable prompt template** | Keeps the feature without network/API keys; preserves the validation schema. |
| 6 | Cookie session + `RequireAuth` guards | **Omitted** (optional app-lock deferred) | No accounts in a local app. |
| 7 | TanStack Query optimistic updates | **Direct local writes + Room `Flow`** | Local writes are instant; optimistic bookkeeping unneeded. |
| 8 | Two-column detail layout | **Responsive:** stacked on phone, two-column on tablet | Phone width can't host a fixed sidebar comfortably. |
| 9 | Deadlines as `Date` | **ISO date string + local-TZ overdue** | Date-only semantics; avoids TZ drift. |

## 13. Deferred / Future Scope

- **Cloud sync / backup & multi-device** (account + backend or BaaS).
- **In-app AI generation** (call an LLM API to build a roadmap from a prompt) — flips the offline guarantee; off by default.
- **Biometric / PIN app-lock** for privacy.
- **Reminders / notifications** for upcoming or overdue deadlines (WorkManager).
- **Home-screen widget** showing next steps / nearest deadline.
- **Templates / duplicate roadmap** to start from a previous structure.
- **Step interdependencies** (blocking/ordering beyond a flat checklist).
- **Cross-feature links** (attach resources or notes to steps), if other modules are later built.

## Appendix B — Operations (from pathforge's 14 endpoints)

Roadmap: list (by archived) · create · get (with children) · update (title/description/deadline/archived) · delete (cascade).
Milestone: add · update · delete (cascade) · reorder.
Step: add · update (title/links/completed → recompute) · delete (recompute) · reorder.
Bulk: import (paste-JSON, atomic).
